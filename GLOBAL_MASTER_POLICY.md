# 🛡️ GLOBAL MASTER POLICY: FOUNDRY v10.1
*Absolute mandate for all projects, agents, and sub-agentic swarms*

## 🧬 I. THE "NEVER DELETE" PROTOCOL
1.  **Strict Additivity:** No historical logic, script, or documentation is to be deleted.
2.  **Legacy Preservation:** Any modification to existing core logic MUST be preceded by a `_LEGACY` backup (e.g., `script_LEGACY.py` or `.matrix_ide/core/backup/`).
3.  **Audit Mandate:** Agents MUST audit every 'replace' or 'write' operation to ensure no non-empty lines are lost without a verified recovery path.

## 🤝 II. BINOMIAL DOUBLE-CONSENT
1.  **Phase Transition:** Major architectural shifts (OS builds, RAG hardening, Syncing) MUST prompt with `[1] PROCEED / [2] ABORT`.
2.  **Plan First:** No execution shall occur without a granular, phased manifest (e.g., 500-step roadmap) being drafted and approved first.

## 🧪 III. THE SCIENTIFIC METHOD
1.  **A/B Testing:** All code advancements MUST be logged in `SCIENTIFIC_LOG.md` with a hypothesis (Variant A vs Variant B) and measurable success criteria (RAM, Latency, Stability).
2.  **Performative Validation:** Every change MUST produce a side-effect (log, test result, or success vault entry) to be considered complete.

## 🎓 IV. PEDAGOGY & LIBRARY SYNC
1.  **Viper Synchronization:** Every positive logic move MUST be incrementally updated to the `VIPER_SCRIPT_LIBRARY`.
2.  **Success Vaulting:** Patterns reaching >95% fitness MUST be stored in the `SUCCESS_VAULT` for recursive self-training.
3.  **Handoff Excellence:** Completing a phase requires a `HANDOFF_FLASH.md` to train sub-agents (Flash/Flash Lite) for the next iteration.

## 🏗️ V. SUBSTRATE-FIRST ARCHITECTURE
1.  **Fencing:** Adhere to physical boundaries (eMMC for State, SD for Weights).
2.  **32-bit Optimization:** All logic must respect <512MB RAM constraints and thermal throttling safety (42°C ceiling).

*A foundational truth for all Foundry-class systems*
1. **Deterministic Reflection:** The AI is a mathematically deterministic and probabilistic mirror of the input variable set.
2. **Input Accountability:** There is no "unwanted behavior" independent of input variables; errors in output are a direct mapping of errors or ambiguities in the input vector.
